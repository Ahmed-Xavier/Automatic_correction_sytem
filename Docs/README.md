\# Automated Examination Correction System



\*\*Project type:\*\* Desktop application  

\*\*Language:\*\* Python  

\*\*GUI framework:\*\* Tkinter / ttk  

\*\*Image processing:\*\* OpenCV  

\*\*Database:\*\* SQLite  

\*\*Primary input:\*\* Scanned examination documents, Excel files  

\*\*Primary output:\*\* Master examination results in Excel



\---



\# 1. Project Overview



The goal of this project is to develop a desktop application that automates examination document processing, QCM correction, numerical grade extraction, student identification, and results management.



The system is designed around three cooperating Tkinter applications:



1\. \*\*Student Barcode Creator:\*\* Generates student barcode identifiers, printable barcode sticker sheets, and an Excel mapping file.

2\. \*\*Answer Key Manager:\*\* Allows teachers to create QCM answer keys, configure grading rules, and export examination correction configurations to Excel.

3\. \*\*Examination Correction System:\*\* The main application. It imports the Excel outputs from the two companion applications, processes scanned examination documents, identifies students, calculates grades, and generates the final results workbook.



The three applications can operate independently. The main Examination Correction System must be able to access and import their generated Excel files without requiring the applications to be merged into one codebase.



The complete workflow should eliminate:



\- Manual correction of QCM examinations.

\- Manual transcription of grades.

\- Manual association of scanned documents with students.

\- Manual consolidation of examination results.



The system must process QCM papers and non-QCM score sheets together in the same scanner batch.



\## 1.1 Main Objectives



\- Automatically identify students using barcodes.

\- Detect the type of each scanned document.

\- Read QCM answers using OMR.

\- Compare student answers with teacher-provided answer keys.

\- Calculate QCM grades automatically.

\- Read numerical grades from non-QCM score sheets.

\- Import student information from Barcode Creator Excel files.

\- Import answer keys and grading configurations from Answer Key Manager Excel files.

\- Generate a centralized database of examination results.

\- Export all results to Excel.

\- Preserve scanned documents and processing history.

\- Provide manual review for uncertain recognition results.

\# 3. Physical Examination Workflow



There are two examination document types.



\## 3.1 QCM Examination Paper



Every QCM answer sheet contains its own barcode.



The barcode identifies the student and examination through the Barcode Creator mapping.



Example:



```text

BARCODE: MATHEMATICS-8F29A71C



SUBJECT: MATHEMATICS



QCM



Question 1: A  B  C  D

Question 2: A  B  C  D

Question 3: A  B  C  D

Question 4: A  B  C  D

...

```



Requirements:



\- Every QCM response sheet has a barcode.

\- The barcode must be readable after scanning.

\- The sheet must follow a standardized OMR layout.

\- The sheet must have registration marks.

\- The sheet must contain fixed answer-bubble positions.

\- The number of questions must match the corresponding examination configuration.



No separate score sheet is required for QCM papers.



\## 3.2 Non-QCM Examination Score Sheet



For written or non-QCM examinations, only the completed score sheet is scanned.



The teacher evaluates the student's written exam and manually fills in the score sheet.



The score sheet contains:



\- Student barcode.

\- Four numeric digit columns.

\- Bubbles numbered 0–9 in every column.

\- Permanently printed decimal separator.



The four columns represent:



| Column | Meaning |

|---|---|

| 1 | Tens |

| 2 | Units |

| 3 | Tenths |

| 4 | Hundredths |



Example:



```text

Tens | Units | . | Tenths | Hundredths

&#x20; 1  |   5   | . |    5   |      0



Score = 15.50

```



Requirements:



\- The score sheet has its own barcode.

\- Only the score sheet needs to be scanned.

\- The system must identify it as a numerical score sheet.

\- The system must read the four digits.

\- The system must validate the score against the examination's maximum grade.

\# 4. Scanner Input and Mixed-Batch Processing



The scanner output folder is the entry point for examination documents.



Example:



```text

data/

└── scans/

&#x20;   ├── batch\_001.pdf

&#x20;   ├── batch\_002.pdf

&#x20;   ├── scan\_001.png

&#x20;   └── scan\_002.tiff

```



\### Important workflow decision



\*\*QCM papers and non-QCM score sheets can appear together in the same batch.\*\*



The application must not require the user to separate them before scanning.



For example, a batch could contain:



```text

Page 1: QCM Mathematics

Page 2: Score Sheet Physics

Page 3: QCM Mathematics

Page 4: Score Sheet Electronics

Page 5: QCM Physics

Page 6: Score Sheet Mathematics

```



Every page must be processed independently.



\### Supported formats



\- PDF.

\- PNG.

\- JPEG.

\- TIFF.



\### File ingestion requirements



1\. Monitor a configurable input folder.

2\. Detect new files.

3\. Wait until a file is completely written before processing.

4\. Register the file as a scan batch.

5\. Convert PDF pages into individual images.

6\. Extract TIFF pages where applicable.

7\. Assign unique internal page identifiers.

8\. Preserve original files.

9\. Track processing status.

10\. Prevent duplicate imports.



The user must also be able to manually select files or folders.



\### Recommended scanning settings



| Setting | Recommendation |

|---|---|

| Paper size | A4 |

| Resolution | 300 DPI |

| Color mode | Grayscale |

| Format | Multi-page PDF or TIFF |

| Compression | Lossless where available |

\# 7. Document Classification



The system must recognize three possible document classes:



1\. QCM answer sheet.

2\. Numeric score sheet.

3\. Unknown document.



Classification must happen independently for every page.



\### Recognition signals



Use:



\- Registration mark positions.

\- Page geometry.

\- Barcode region.

\- QCM answer-grid structure.

\- Numeric score-grid structure.

\- Standardized template matching.



The barcode should be detected and decoded independently of document classification.



Do not rely exclusively on the barcode to identify the document type.



Example classification result:



```python

{

&#x20;   "document\_type": "qcm",

&#x20;   "classification\_confidence": 0.98,

&#x20;   "barcode\_region\_detected": True

}

```



This is an illustrative data structure. Implement actual classification and validation.



If the page cannot be confidently classified, send it to manual review.



Centralize template definitions and calibration parameters. Do not scatter hardcoded coordinates across recognition modules.

\# 8. Barcode Recognition and Student Identification



Use a barcode reader compatible with the Barcode Creator output.



Prefer Code 128 if that is the format used by the companion application.



Requirements:



\- Read barcode values from scanned pages.

\- Handle reasonable rotation and image-quality variations.

\- Validate decoded values.

\- Search imported barcode mappings.

\- Retrieve the associated student.

\- Retrieve the subject and Exam ID.

\- Flag unknown barcodes.

\- Flag conflicting mappings.



Example:



```text

Detected barcode:

MATHEMATICS-8F29A71C



Database lookup:



Student: Ahmed

Subject: Mathematics

Exam ID: MATH-2026-01

```



The barcode is unique per examination.



Use a stable Student ID where available to associate the same student across multiple examinations.



Never merge students solely because their names look similar.



Never guess an unknown student identity.

\# 9. QCM Recognition and Automatic Correction



The QCM correction pipeline must be independent of the score-sheet reader.



\## 9.1 Image Alignment



\- Detect registration marks.

\- Correct page rotation.

\- Correct perspective distortion.

\- Align the page to the QCM template.

\- Locate expected answer-grid regions.



\## 9.2 Bubble Detection



Use OpenCV to inspect predefined bubble positions.



For each question, return one of:



\- Single answer selected.

\- Unanswered.

\- Multiple answers selected.

\- Uncertain mark.



The system must distinguish filled bubbles from:



\- Printed outlines.

\- Printed letters.

\- Scanning noise.

\- Light marks.

\- Stray pen marks.



Do not accept ambiguous detections automatically.



\## 9.3 Answer Key Lookup



Use the barcode mapping to identify the examination.



Retrieve the corresponding published answer key using its Exam ID and version.



Never select an answer key using the subject name alone.



A subject can have multiple examinations with different answer keys.



\## 9.4 Grade Calculation



Compare each detected answer against the answer key.



Apply the configured grading rules.



Example:



```text

Total questions: 40

Correct: 32

Incorrect: 5

Unanswered: 3



Final score: 16.00 / 20

```



The numbers are illustrative.



Store:



\- Detected answer for every question.

\- Correct answer.

\- Question status.

\- Points awarded.

\- Total score.

\- Answer key version used.



If no valid answer key is available, do not calculate a final grade.



Preserve the scan and flag the paper for review.

\# 10. Non-QCM Score Recognition



The score-sheet reader must decode the four numeric columns.



\## 10.1 Score Sheet Layout



| Column | Meaning |

|---|---|

| 1 | Tens |

| 2 | Units |

| 3 | Tenths |

| 4 | Hundredths |



Each column contains bubbles numbered 0–9.



The decimal separator is printed between columns 2 and 3.



\## 10.2 Processing



1\. Align the page.

2\. Locate the four digit columns.

3\. Identify the selected bubble in each column.

4\. Detect empty columns.

5\. Detect multiple selections.

6\. Detect uncertain marks.

7\. Reconstruct the numerical score.

8\. Validate against the maximum examination score.



Example:



```text

Detected digits:



1 | 5 | 5 | 0



Final score:



15.50 / 20

```



Possible outcomes:



\- Valid score.

\- Missing digit.

\- Multiple selected bubbles.

\- Uncertain mark.

\- Invalid score.

\- Score exceeds maximum grade.



Do not silently repair an uncertain score.



Send uncertain results to manual review.

\# 11. Validation and Manual Review



The system must have a validation layer between recognition and final result storage.



Potential warnings:



\- Unknown barcode.

\- Unreadable barcode.

\- Conflicting student mapping.

\- Unknown examination.

\- Incorrect document type.

\- Missing answer key.

\- Multiple QCM bubbles.

\- Uncertain QCM mark.

\- Empty numeric digit column.

\- Multiple numeric bubbles.

\- Score exceeding the maximum.

\- Duplicate document.

\- Duplicate examination result.



Only valid and confirmed results should be accepted as final grades.



The manual review interface must allow the user to correct recognition errors and record the reason for each correction.



Preserve the original recognition output even when a human changes the result.

\# 18. Testing Requirements



Testing must use both synthetic and real printed/scanned documents.



\## 18.1 Barcode Creator Excel Tests



Test:



\- Correct workbook import.

\- Multiple workbook imports.

\- Missing columns.

\- Empty student names.

\- Duplicate barcode IDs.

\- Conflicting examination mappings.

\- Duplicate student records.

\- Missing Exam IDs.

\- Modified workbooks.



\## 18.2 Answer Key Excel Tests



Test:



\- Complete answer keys.

\- Missing questions.

\- Invalid answer options.

\- Duplicate question numbers.

\- Different question counts.

\- Equal weighting.

\- Custom weighting.

\- Incorrect grading configurations.

\- Multiple answer-key versions.



\## 18.3 QCM Recognition Tests



Test:



\- Correct answers.

\- Incorrect answers.

\- Unanswered questions.

\- Multiple selected bubbles.

\- Light pencil marks.

\- Heavy pen marks.

\- Rotated pages.

\- Low-quality scans.

\- Unknown barcodes.



\## 18.4 Score-Sheet Tests



Test scores such as:



\- 00.00

\- 09.50

\- 15.75

\- 19.99

\- 20.00



Also test:



\- Empty columns.

\- Multiple selected bubbles.

\- Uncertain marks.

\- Invalid scores.

\- Scores exceeding the maximum.



\## 18.5 Mixed-Batch Tests



Example:



```text

Page 1: Mathematics QCM

Page 2: Physics Score Sheet

Page 3: Mathematics QCM

Page 4: Electronics Score Sheet

Page 5: Physics QCM

Page 6: Mathematics Score Sheet

```



Verify that each page is independently identified and processed.

\# 19. Engineering Rules



These rules must be followed throughout implementation.



1\. Do not guess student identities.

2\. Do not guess correct answers.

3\. Do not automatically accept ambiguous OMR readings.

4\. Do not regenerate existing barcode assignments.

5\. Do not use subject name alone to select an answer key.

6\. Do not silently overwrite existing examination results.

7\. Preserve original scans.

8\. Track processed pages to prevent duplicates.

9\. Make batch processing resumable.

10\. Record all manual modifications.

11\. Keep recognition and grading logic independent.

12\. Centralize OMR template definitions and coordinates.

13\. Keep the GUI responsive during processing.

14\. Use background workers for lengthy operations.

15\. Access Tkinter widgets only through the main GUI thread.

16\. Validate Excel files before importing.

17\. Keep imported data persistent in SQLite.

18\. Do not assume companion applications share the same codebase.

19\. Use Excel files as explicit integration interfaces between applications.

20\. Do not delete or overwrite existing repository work without justification.

\# 21. Instructions to the Coding Agent



Before implementing anything:



1\. Inspect the complete existing repository.

2\. Identify the current project structure and existing dependencies.

3\. Determine whether the Barcode Creator and Answer Key Manager are already implemented or still need to be developed separately.

4\. Locate and inspect actual Barcode Creator Excel output files if available.

5\. Locate and inspect actual Answer Key Manager Excel output files if available.

6\. Inspect available QCM and score-sheet PDF templates.

7\. Identify reusable components.

8\. Confirm the actual column names, worksheet names, data types, and workbook structures of the companion applications.

9\. Propose the implementation plan based on the real repository.



Do not invent workbook schemas when actual examples are available.



If the companion applications or their Excel examples are not accessible, define and document an expected import schema, but make it configurable and validate it.



\### Implementation expectations



\- Implement functional software, not just interface mockups.

\- Keep modules independent and maintainable.

\- Use persistent database storage.

\- Build automated tests.

\- Use real test documents when available.

\- Keep the application responsive.

\- Handle errors explicitly.

\- Do not claim a feature works until it has been tested.



At the end of every development phase, report:



\- Features implemented.

\- Files created.

\- Files modified.

\- Tests performed.

\- Test results.

\- Remaining issues.

\- Exact installation and launch commands.



\### Final objective



Deliver a complete local desktop examination processing system that can:



1\. Read Excel student-barcode mappings generated by the separate Barcode Creator Tkinter application.

2\. Read Excel answer keys and grading configurations generated by the separate Answer Key Manager Tkinter application.

3\. Receive mixed batches of scanned QCM papers and non-QCM score sheets.

4\. Identify every document and read its barcode.

5\. Automatically correct QCM examinations.

6\. Automatically extract numerical grades from non-QCM score sheets.

7\. Match all results with the correct student and examination.

8\. Provide manual review for uncertain documents.

9\. Maintain a reliable local database.

10\. Generate a master Excel workbook containing student names, subjects, examination identifiers, exam-specific barcodes, and grades.



\*\*The three applications must remain logically independent, with Excel workbooks serving as the integration interface between the two companion applications and the central Examination Correction System.\*\*
